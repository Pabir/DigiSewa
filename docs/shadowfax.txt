DownloadAPI BlueprintShadowfax Unified API for Forward IntegrationsIntroductionYou can integrate with Shadowfax's Last Mile Customer Delivery Platform by using the Unified API Collection. Unified APIs provide a singular interface to enable Marketplace Seller and Warehouse models of operations. These APIs support end to end order lifecycle starting from Pincode serviceability to order status tracking until delivery.GlossaryDCs and HubsDC: Large facilities typically located in the outskirts of a city where all shipments(intercity and intracity both) are processed.
Hub: Small facilities located across the city from where last-mile delivery and first mile pick up happens.Following terms are defined concerning a shipment's locationOrigin Hub:
This is the first Shadowfax facility where a packet reaches directly from the seller or customerOrigin DC:
This is the first DC where a packet is sent from the client Warehouse or origin hub to process further.Destination Hub:
This is the last shadowfax facility where a packet reaches before delivering to customer or sellerDestination DC:
This is the last DC where a packet is sent before sending to the destination hub or client WarehouseVia DC:
All DC's, other than origin and destination where a shipment has to go through. Manifest bags are not opened at these DCs and will be directly passed on to the next location.Type of OperationsForward Operations:
Orders that are originating at client warehouse or seller side and are to be delivered to end customer.

Reverse Operations:
Return orders that are originating at the customer side or forward orders that could not be delivered to the customer and are to be returned to the client warehouse or seller.
Miscellaneous
AWBs:
Unique Identification Number for each item/packet
LOR:
Letter of Receipt, a document for acknowledging the delivery or receipt of shipments/ packets
POD(Proof of Delivery):
A receipt of pickup and delivery of itemsAuthenticationShadowfax API uses Token Authentication. The Staging and Production API keys will be shared with you from the Shadowfax Team via an automated email.

Update Order Details
Update Order Data
Request to Update Order Data
The endpoint allows you to edit delivery_details, pickup_details,return_details and order status for an order.The API functionalities are as follows:This API can be used to update the order status as rts / rto / reopen_ndr only if the current status of the order is either on_hold or cancelled_by_customerThe API can be used to update customer details along with the Pincode, but the Pincode can only be updated twice per order and only for intra-city orders.The mandatory/required attributes should be passed as null if they do not need to be updated.The Pincode cannot be updated when the current status of the order is delivered .This API can be used to update the payment mode of the order to prepaid if the cod_amount is passed as 0, but the updation can only be done after the pickup phase i.e post the item is picked.The shipment weight can be updated only once, and only while the shipment is in new status.The delivery_details can be updated before OFD, the return_details can be edited until the order is cancelled_by_customer and pickup_details can be edited until the order is assigned_for_seller_pickup.

Order Cancellation
Order Cancellation
Cancel a Request
This endpoint cancels marketplace or warehouse orders using the AWB Number or unique client order id, along with the cancellation reason.For successful cancellation, we give a Response message as “Request has been marked as cancelled” & 200 as response code.For below mentioned statues, the API queues the cancellation request, returning 'Request is queued for cancellation' & 304 as response code.Out for pickup (ofp)received at reverse hub (recd_at_rev_hub)Out for delivery (ofd)Bag In Transit (bag_in_transit)Bag Received at Via (bag_received_at_via)The cancellation is executed when the shipments are received in the next SFX facility. In case the shipment is “Delivered”, then the canceling request is not executed.Cancellation after delivery results in failure, returning 'Order cannot be cancelled. Invalid state.' & 400 as response code.
